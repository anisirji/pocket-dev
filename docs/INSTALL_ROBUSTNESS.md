# Install robustness: decisions

Trigger: on a second Windows PC (Node 26, PowerShell) `npm i -g anisirji/pocket-dev` (a GitHub install) printed `TAR_ENTRY_ERROR ENOENT ... scripts\autostart.sh`, then `spawn cmd.exe ENOENT` for `node_modules\node-pty`: node-pty's install script could not start because its folder was never unpacked. Before that, `npm i anisirji/pocket-dev` (no `@`, no `-g`) installed into the Desktop folder and `pocket-dev` was not recognised.

Goal: no native-module problem can make `npm install -g @anisirji/pocket-dev` fail, and the app says exactly how to repair what is missing.

## Decisions

1. **node-pty is an `optionalDependency`.** npm skips an optional package whose download, unpack or install script fails and finishes the install. node-pty 1.1.0 ships N-API prebuilds for darwin-x64/arm64 and win32-x64/arm64 (not tied to a Node version, so Node 26 is fine); Linux and other targets build with node-gyp, which needs a compiler. Its own `install` script is `node scripts/prebuild.js || node-gyp rebuild`. The lockfile marks node-pty and node-addon-api `optional` and drops `hasInstallScript` from the root (regenerated with `npm install --package-lock-only`).
2. **Pocket Dev has no npm lifecycle scripts.** The old `postinstall` only made node-pty's `spawn-helper` executable. A real test showed that a Git install (`npm install -g git+file://...`) failed on it with `getcwd ... uv_cwd ENOENT`: npm ran the script in a folder that no longer existed, the same class of failure as the Windows report. The script is gone. `pty-loader.js` makes the helper executable when it loads node-pty (idempotent, never throws), which also repairs `npm install --ignore-scripts`: a real test without that fix gave `posix_spawnp failed`.
3. **The app never imports node-pty directly.** `pty-loader.js` does a guarded dynamic import and returns `{available, pty, reason, hint, command}`; it never throws. `server.js` and `terminal-host.js` use it. `POCKET_DEV_FORCE_NO_PTY=1` makes it report "unavailable" (for tests and screenshots only).
4. **Without node-pty:** the server starts and logs one `Warning: terminals are off: <reason>. Fix: pocket-dev doctor --fix` line. `POST /api/sessions` and Resume answer 503 `Terminals are not available on this computer: <reason>. <hint>`; the terminal WebSocket is refused with 503; `GET /api/sessions` is `[]`; `GET /api/terminals` returns `{available, reason, hint, command}`; `GET /api/health` has `terminals: {available, reason}`. The terminal host process is not started. The phone Terminal view shows a card (`public/terminals-off.js`) with the reason, the command, a Copy button and a link to the Troubleshooting section, and hides the tab bar, input bar and key bar.
5. **`pocket-dev doctor`** (`doctor.js`, reusing setup.js detection): Node version, how it was installed (global, local, npx, source checkout; from GitHub when the whole repository is present), npm's global folder on PATH, the `pocket-dev` command on PATH, a one-second real shell through node-pty, Git/Claude/Codex/GitHub CLI/cloudflared, a writable settings folder, the port, a Windows firewall hint. Required rows (Node, terminals, settings folder) decide the exit code (0 or 1); the rest are recommended or optional and only print their next command. `--fix` is limited to node-pty: `npm rebuild node-pty` (when the folder exists), then `npm install --no-save node-pty@<range>` (when it is missing or still broken), both run inside the Pocket Dev folder, each shown first with `[Y/n]` (`--yes` skips the question; a non-interactive run only prints). Never `sudo`, never `curl | sh`. If it still fails it prints compiler guidance (Visual Studio Build Tools and Python on Windows, `xcode-select --install` on macOS, `build-essential python3` on Linux) for the person to run. A temporary npx copy is refused: install it first. `pocket-dev setup` has a `terminals` step (and a line in `--check`) that uses the same check and repair.
6. **Old Node.** `bin/pocket-dev.js` is a tiny file with only old syntax: it checks the version first and prints `Pocket Dev needs Node 22 or newer, and this computer has Node X.` with the download link, then loads `bin/cli.js` by dynamic `import()` (a static import would run before the check). `POCKET_DEV_FAKE_NODE` lets a test pretend to be another version. Node older than about 12 cannot parse even this file; that is accepted.
7. **Windows files.** `.gitattributes` forces LF for scripts and JSON (a CRLF shebang breaks `env node`), CRLF for `.ps1`, and leaves `public/vendor` untouched. No BOM or CRLF was found in tracked source. `realRun` now quotes a command path with spaces when it goes through a shell (`C:\Program Files\nodejs\npm.cmd`).

## Not changed

`pocket-dev service` (shell scripts, `tail`) is still macOS only on the command line; Windows uses `service install` through setup. That was out of scope.

## What could not be verified here

No Windows machine was available. Verified on macOS (arm64, Node 22.17): real `npm pack` installs into temporary prefixes (normal, `--ignore-scripts`, node-pty removed, Git install), doctor and `doctor --fix` against a really missing node-pty, the server without node-pty, and the phone card in headless Chrome at 390x844. Windows behaviour is covered by tests that inject a Windows platform, PATH and paths (`test/doctor.test.mjs`); npm's handling of an optional dependency whose unpack failed on Windows, antivirus behaviour, the real compiler guidance commands, and `npm.cmd` quoting are untested on Windows.
